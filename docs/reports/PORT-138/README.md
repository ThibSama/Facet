# PORT-138 — visual evidence

Generated by `tools/shell-toggle-shots.mjs`, against a production build served
by PHP's built-in server:

```
npm run build
php -d variables_order=EGPCS -S 127.0.0.1:8765 -t public public/index.php
node tools/shell-toggle-shots.mjs docs/reports/PORT-138 http://127.0.0.1:8765
```

Every shot is at `deviceScaleFactor: 2`. Except where noted below, all of them
emulate `prefers-reduced-motion: reduce`, which stops the skill ribbons and
cancels section entry — that is what makes two runs produce the same bytes, and
it costs exactly the two things a still photograph could not have shown anyway.

**None of this is a test.** The behaviour is asserted in
`tests/E2E/theme-toggle.spec.ts` (15 cases × 3 engines) and in the PHPUnit
shell gates. What is here is the part a human has to judge.

### The transition — time-dilated, and not evidence of timing

`transition-to-dark-slowed-*.png` and `transition-to-light-slowed-*.png`.

These are the **only** shots taken with motion enabled, and they are the only
ones that are not reproducible.

The real transition is **360ms** (`--facet-duration-slow`). Capturing a
screenshot costs more than a frame of that, so sampling the real thing on a
timer yields a strip of near-identical settled states and tells a reviewer
nothing except how fast this machine is. So the duration token is overridden to
**10×** for these frames only, and the strip is sampled across the dilated
transition. The script asserts the override actually landed and fails loudly if
it did not, because a strip of settled frames looks like evidence and is not.

Read them for the *shape* of the interpolation — where the body is when the
clouds have gone, how late the stars arrive relative to the sky. Do not read
them for timings. The timings are asserted in the E2E suite, against the
properties CSS transitions to.

`-00-before` and `-99-after` are the settled ends.

## The skill ribbons' entry mask

| File | What it shows |
| --- | --- |
| `skills-left-edge-light.png`, `skills-left-edge-dark.png` | **The subject of the change.** The entry edge at the scale the problem was visible at |
| `skills-live-light.png`, `skills-live-dark.png` | The whole section with the ribbons live |
| `skills-static-light.png`, `skills-static-dark.png` | The reduced-motion / no-JavaScript state: a wrapping list, no mask at all |

The `-live-` and `-left-edge-` shots run **with motion enabled**, and are
therefore not byte-reproducible: the strip is moving. That is deliberate. The
mask being changed only exists on a live ribbon — `[data-facet-ribbon='live']`
— so a shot of the static ribbon would have been a picture of the thing that is
not under review. What *is* reproducible is the property: the first chip after
each category label is fully opaque rather than half-dissolved beneath it.

Compare against `docs/reports/PORT-136/desktop-*-skills.png` for the before.

| `header-{320,390,412,768,834,1024,1280,1512,1920}-dark.png` | Every validated width |

At 320–767 the collapse control is present and the nav is behind it; from 768
the collapse control is removed by the shared layer and the routes are inline.
The theme control is in every one of them, at 44 × 44, never overlapping the
navigation. The E2E suite asserts the non-overlap and the absence of horizontal
overflow at all nine widths.
